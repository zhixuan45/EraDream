# 扩展包与剧情嵌套架构设计文档

本文档定义了 EraDream 项目中针对扩展包 (Extension)、剧情包嵌套 (Nested Story) 以及安全权限控制的架构标准。

## 1. 多层级扩展模型

为了平衡扩展包的自由度与用户安全性，引擎采用三层扩展架构：

1. **层级 1 - 纯数据驱动 (纯 JSON) 【绝对安全】**
   - 仅包含 manifest.json、媒体资源与 JSON 格式的配置（包括剧情、行为树 Behavior Tree、UI 菜单扩展等）。
   - **全面扩展的 UI 控制能力**：纯 JSON 模式下，扩展包不仅能配置剧情，还能直接定义、追加甚至覆写原有的系统菜单选项（例如自定义“训练”的子项目，或是自定义“外出”的地点及行为）。同时也能自定义外出/训练的结果行为。
   - 完全依赖引擎自带解析器，无缝接入 GlobalGameState 进行自定义数值存储，静默加载，无需任何安全警告。
2. **层级 2 - 受限 API 沙盒 (安全 C#) 【安全受控】**
   - 允许使用 C# 编写逻辑，但仅限调用引擎专门开放的无害 API。
   - 经过静态扫描确认不包含任何底层高危库的引用，自动加载。
3. **层级 3 - 不受限 C# DLL 【高危预警】**
   - 包含读取 System.IO、System.Net 或 DllImport 等高危系统权限的底层代码。
   - 加载前会被 **静态 IL 安全扫描器** 拦截，在 UI 标红并列出申请的高危权限。
   - 必须由玩家手动勾选同意授权后方可加载。

## 2. 嵌套加载与优先级控制

扩展包支持将独立的“剧情包 (Story)”作为子模块进行“套娃”式包含。为了避免资源和命名空间互相冲突，采用 **“按需显式声明”** 策略：

- **显式声明控制**：在扩展包的 manifest.json 中，作者需要显式配置资源和变量的覆盖策略。
- **示例机制**：系统不会盲目覆盖现有文件。作者需明确指出哪些资源是独立隔离的，哪些资源旨在覆盖本体逻辑（如修改默认背景或核心事件）。

## 3. JSON 数据与逻辑的扩展融合

扩展包通过 JSON 注入新的系统数据（如决策树、自定义数值、训练/外出UI选项）时，系统采用 **“混合自适应模式”** 进行融合：

- **追加/合并 (默认)**：扩展包提供的 JSON 节点（如新增一个特殊的“特训”菜单项，或决策树的新分支）将作为新的分支，追加到现有的数据结构末尾，保证不破坏基础逻辑的连贯性。
- **覆盖/替换 (特例)**：如果扩展包的目的是修改既有规则，作者可以在特定 JSON 数据节点（如原本的系统“休息”选项）中显式添加 override: true 标记，精准替换掉本体特定的选项配置、决策树节点或基础行为。

## 4. 混合包安全处理与降级策略

对于既包含安全 JSON 静态数据，又附带 C# DLL 的“混合型”扩展包，引擎实行 **“整体安全阻断”** 原则：

- 如果混合扩展包的 DLL 被扫描出含有高危权限，且玩家在警告 UI 中 **拒绝授予** 权限。
- 引擎将 **一律拒绝加载** 整个扩展包（包含其 JSON 数据）。
- **拒绝部分加载**：不采取降级只加载 JSON 的妥协手段。此举旨在防止代码与数据割裂而引发的业务逻辑断层、存档损坏或不可预知的严重错误。
