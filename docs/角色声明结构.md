# EraDream 角色声明结构说明书 (Character Declaration Specification)

## 1. 概述
在 `EraDream` 架构中，角色的定义采用了**数值与表现解耦**的设计。一个完整的角色配置由两个核心 JSON 文件组成，分别服务于养成模块和剧情模块。

## 2. 文件分布规范
对于**正式马娘包 (Character Pack)**，配置文件存放于 `.umaext` 包内的 `Data/` 目录：
- `Data/simulation.json`: 定义养成相关的基础数值、心情、成长率。
- `Data/actor_config.json`: 定义剧情演出的立绘映射、差分表情、悬浮对话及语音。

对于**剧本客串角色 (Guest Actor)**，直接在剧本目录下的 `characters.json` 中以数组形式声明 `actor_config.json` 的内容。

---

## 3. 养成数据规范 (`simulation.json`)

```json
{
  "identity": {
    "internal_id": "命名空间:角色唯一ID",
    "full_name": "角色全名",
    "short_name": "简写（用于UI）",
    "personality_id": "性格标识符（对应逻辑判定）"
  },
  "stats": {
    "initial": {
      "speed": 120, "stamina": 110, "power": 115, "guts": 95, "intelligence": 85, "skill_points": 10
    },
    "conditions": {
      "motivation": 3,           // 初始心情 (1-5)
      "energy": 100,             // 初始个人体力
      "affection": 0             // 初始羁绊
    },
    "growth_bonus": {
      "speed": 0.20,             // 训练加成（0.2 = +20%）
      "stamina": 0.10,
      "power": 0.0,
      "guts": 0.0,
      "intelligence": 0.0
    },
    "custom_stats": {
      "plugin_id:stat_name": 100 // 玩法扩展包注册的自定义数值初始化
    }
  }
}
```

---

## 4. 表现数据规范 (`actor_config.json`)

```json
{
  "actor_id": "必须与 simulation 中的 id 一致",
  "display_name": "对话框显示名称",
  "visuals": {
    "default_sprite": "Assets/Sprites/body_idle.png",
    "expressions": {
      "表情ID": "资源路径",
      "0": "Assets/Sprites/body_normal.png",
      "1": "Assets/Sprites/body_happy.png"
    },
    "stickers": {
      "贴纸ID": {
        "path": "资源路径",
        "offset": [x, y],
        "scale": 1.0
      }
    }
  },
  "barks": [
    {
      "condition": "触发条件表达式 (如: energy < 30)",
      "text": "悬浮对话文本",
      "expression": "对应 visuals 中的表情ID",
      "sticker": "对应 stickers 中的贴纸ID (可选)",
      "voice": "专属语音路径 (可选，若为空则触发 fallback)"
    }
  ],
  "audio": {
    "typing_sound": "打字音效路径",
    "fallback_voices": [
      "通用语音路径1.ogg",
      "通用语音路径2.ogg"
    ]
  }
}
```

---

## 5. 命名空间与路径准则
1. **ID 唯一性**：严禁使用 `speed` 或 `default` 等通用词作为 `actor_id`。推荐格式：`作者名:马娘名`。
2. **资源路径**：在包内声明时，路径应以 `Assets/` 开头（相对于包根目录）。
3. **客串角色声明**：若为剧本专属角色，无需 `simulation.json`，仅需在剧本目录的 `characters.json` 数组中填入上述 `actor_config` 结构即可。

---

## 6. 后续 Agent 开发指引
- **编辑器 Agent**：在创建“角色编辑器”时，应提供双面板切换（数值面板 vs 表现面板），并自动校验 ID 格式。
- **资源包 Agent**：在打包 `.umaext` 时，必须确保 `manifest.json` 中的 ID 与本规范中的 `internal_id` 保持同步。
